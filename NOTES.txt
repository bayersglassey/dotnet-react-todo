I learned a couple of things there. The major differences seem to be:
* The MVC app does the following (presumably these are middlewares):
    app.UseRouting();
    app.UseAuthorization();
    app.MapStaticAssets();
    app.MapControllerRoute(...etc...).WithStaticAssets();
* The API app does the following:
    app.MapGet("/weatherforecast", () => { ...etc... }).WithName("GetWeatherForecast");

So that makes sense. We can "map" MVC controllers and API endpoints.
Let's take a step back for a second, and check the assignment's instructions.
In fact, we're not being asked to do MVC; we're being asked to use React or Vue on the frontend.
So actually, we just need an API on the backend, not controllers etc.

In Django, there is Django REST Framework, where we can have API endpoints automatically generated for our models.
I wonder if there's something like that in .NET Core?..
Ideally, we want API endpoints and also front-end components generated for us.
Does Blazor do that?.. let's go follow the tutorial: https://dotnet.microsoft.com/en-us/learn/aspnet/blazor-tutorial/install
...nope, Blazor looks like MVC, with a "Razor" templating language. Very "classic ASP".

So, I googled "dotnet core equivalent of django rest framework", and found this:
https://www.reddit.com/r/dotnet/comments/hndlfb/django_rest_framework_equivalent_with_net/
> Entity Framework is the ORM for you. Django's ORM is the most similar experience I've ever had to it.
> Other than that the standard dotnet template is an excellent starting point. For something more advanced I recommend this template: https://github.com/jasontaylordev/CleanArchitecture
> It uses Mediatr with CQRS pattern which may be a bit of an overkill for basic CRUD but on the other hand you will be a bit more prepared if there is need for more advanced business logic.

I remember reading about CQRS once on Martin Fowler's blog: it's where you use different models for reads vs writes, basically.
In our case, we're learning .NET Core by making a TODO app, so let's keep it simple for now and just do CRUD.
So, next let's find an Entity Framework tutorial...
